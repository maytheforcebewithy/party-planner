# Roadmap

What is planned next for Party Planner. Nothing here is a fixed schedule; each
item has an issue with details and a rough plan. Pick one up if you like.

## Planned

**CI workflow** ([#69](https://github.com/maytheforcebewithy/party-planner/issues/69)).
Lint, typecheck, unit tests and the Playwright suite on every pull request, then
a protected main branch.

**Configurable reminder lead time** ([#70](https://github.com/maytheforcebewithy/party-planner/issues/70)).
One day before is the only option today. Let the host pick an hour, a day, three
days or a week, and maybe more than one reminder.

**Tasks and schedule** ([#71](https://github.com/maytheforcebewithy/party-planner/issues/71)).
A to-do list per party and a simple timeline for the day itself, both exported
and imported with the rest.

**Guests from contacts** ([#72](https://github.com/maytheforcebewithy/party-planner/issues/72)).
Pick names from the phone's contacts instead of typing them, storing nothing but
the name.

**iOS project checked in** ([#73](https://github.com/maytheforcebewithy/party-planner/issues/73)).
The generated Xcode project next to the Android one, so the iOS build is
reproducible.

**Recurring parties** ([#74](https://github.com/maytheforcebewithy/party-planner/issues/74)).
A repeat rule that creates the next instance from a finished party.

**Duplicate a party** ([#75](https://github.com/maytheforcebewithy/party-planner/issues/75)).
One tap to reuse a past party as a template.

## Ideas

Further out, not committed yet.

**Third UI language.** The locale files are plain JSON, so another language is
mostly translation work.

**Invitation themes.** A few more looks for the shared invitation image beyond
the current light card.

**Photo per party.** Attach a picture from the phone to a party and show it on
the detail page and the invitation.

## Want to help?

Open an issue or a PR for anything above.
